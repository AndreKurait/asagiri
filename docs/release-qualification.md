# Release qualification

Every main push runs the Engine comparison workflow. Release publication waits for a successful comparison at that exact commit, alongside the platform, UI, security, CodeQL and speed checks. The existing release retry workflow resumes publication when the comparison finishes.

The comparison measures ping, an empty filtered list, container lifecycle, exec output and exit status, and a 64 KiB file round trip through a local volume. Asagiri, Docker and Podman receive the same pinned Alpine image and network settings. Each workload retains all 400 samples per engine, validates its result, and verifies removal of its own fixtures. The [comparison notes and retained results](engine-comparison.md) describe host limitations; these API workloads do not establish application throughput or native desktop performance.

Mac preview identity is checked separately. The published `v0.1.6-dev.98` executable correctly reported `0.1.6-dev.98`, while both numeric Apple bundle fields reported `0.1.6`. The updater previously used that shortened field for its release comparison. Bundles now add `AsagiriVersion` with the complete release version. The updater prefers this explicit identity and continues to read older stable bundles; a malformed explicit identity is rejected.

Both Mac release jobs require the expected bundle identity, native architecture, actual executable `--version`, and matching plist and executable bytes in the update archive. Archive paths are normalized before matching: duplicate paths, case aliases, parent traversal, absolute paths and writes through redirected parents are rejected. Ordinary leaf links for the CLI remain accepted. The jobs retain a separate package-identity artifact without changing the public asset manifest. These checks run after the existing code-signature verification.

The 16 package tests exercise xtask's actual plist template and reject the old preview metadata, a stale executable, the wrong architecture, changed archive contents, path aliases and redirected parents. A separate reproduction of [review comment 4582789429](https://github.com/AndreKurait/asagiri/pull/49#discussion_r4582789429) confirmed that the previous checker accepted a `./` duplicate that macOS's `/usr/bin/tar` used to replace the verified executable bytes. Native Rust tests cover preview ordering, stable compatibility and malformed properties. The official dev.98 bundle served as a negative control for the new metadata gate.

The updater also requires the installed app's designated signing identity and a successful macOS notarization assessment. Older previews cannot bootstrap this metadata change through that updater, and unnotarized preview archives require a verified manual installation. Both checks remain required.
