Its duplicate open replaces the entry and its workers still remove by numeric ID. Its blocking queue send also remains. These behaviors apply to the mechanisms in the fork. A path-adjusted dry run against the baseline index fails at the hunk near upstream line 219. The shallow checkout exposes only the current merge in local history, so it cannot establish downstream PR provenance. The source itself lacks the upstream guard. A direct API fetch could not resolve `api.github.com` in the sandbox.

Adapted the relay guard and socket shutdown from Kiri #515. The relay owns the listeners, uses nonblocking accept with a 20 ms idle interval, and checks per-open identity before worker attach, output and cleanup. Duplicate opens are ignored while an ID is active. A full queue closes its connection so a stalled TCP writer cannot keep the relay input reader waiting on that queue. The existing loopback allowlist, IPv4/IPv6 dialing and TCP write-half shutdown remain in place. Truncated headers now produce the same `UnexpectedEof` as truncated bodies. A synchronous transport write already in progress is subject to the underlying transport's behavior. Pending connects retain the existing per-address timeouts.
