# Reproducing the frozen upstream patches

The November 18, 2026 audit retains the 73 new or changed PR diffs in its local
evidence bundle. Each changed row in `docs/upstream-pr-audit.json` records the
public PR number, base and head commits, merge base (`diff_base`), byte count
and SHA-256 of those bytes.
The frozen commit objects and original patch files remain in the audit workspace.

The target branch can advance after a PR branches from it. The retained
three-dot diff compares the head with that merge base:

```sh
git diff --no-ext-diff BASE_COMMIT...HEAD_COMMIT > kiri-pr-NUMBER.patch
wc -c < kiri-pr-NUMBER.patch
shasum -a 256 kiri-pr-NUMBER.patch
```

Run this in a repository containing the recorded public Kiri commits. If the
objects are absent, fetch those exact commits from `libracoder/kiri` without
changing a checked-out branch:

```sh
git fetch --no-tags https://github.com/libracoder/kiri.git BASE_COMMIT HEAD_COMMIT
```

Compare the generated bytes with both `patch_bytes` and `patch_sha256` in the
audit. A current PR head can differ from the frozen head. Public Git hosting may
eventually stop serving an old unreachable commit; the original retained patch
and commit objects are needed in that case.

For example, the recorded PR #119 patch is reproduced by:

```sh
git diff --no-ext-diff \
  f68a8d2129b99ddb72a89033ec65cbdfdfa709a7...ea5de9476031bb720e20f4b9352debd8258b37c9 \
  > kiri-pr-119.patch
```

It contains **365582 bytes** with SHA-256
`3dba3aca0d6233315ce30416ceb25dc93432be6e8f752c4984eb4e67833ee8fb`.
This procedure was checked against all 73 retained patches. Matching source
bytes establishes the review input; it does not establish implementation
correctness or native-platform qualification.
